# ADR-0003: Translations (i18n)

- **Status:** Proposed
- **Date:** 2026-11-21
- **Decider:** Rashid Ishmail

## Context
Home languages are a non-negotiable (CLAUDE.md §2.4). Requirements from the M1 spec (FR-7, FR-8):
- Every UI string comes from translation files; none hard-coded
- A missing English string **fails the build**
- Switching language is instant and remembered on the device
- Only the strings for the chosen language are downloaded (low data)
- Correct plurals in every language (isiZulu, Sepedi and others have their own rules)
- A pseudo-locale to catch untranslated text in testing
- Translators work in plain files, not code

Scope: this ADR covers **interface text** (buttons, menus, messages). Lesson text is translated as content (ADR-0004).

## Options considered

| | Paraglide JS 2 (inlang) | i18next | Hand-rolled (JSON + `Intl.PluralRules`) |
|---|---|---|---|
| How it works | Compiles each message to a small function at build time | Runtime library loads JSON | Our own ~1 KB loader |
| JS cost | Tiny; unused messages are removed from the bundle | ~15–40 KB runtime | ~1 KB |
| Missing key | Compile/type error, so the build fails | Shows the key at runtime | Needs our own check |
| Plurals / variants | Yes | Yes | Yes, via `Intl.PluralRules` |
| Works with SvelteKit and Astro | Yes (official guides) | Yes | Yes |
| Translator tooling | Plain JSON files plus a web editor | Many tools | Plain JSON |
| Licence | Permissive open source (confirm exact licence in step 4) | MIT | Ours |

## Decision
**Paraglide JS 2**, with messages in `content/i18n/<lang>.json`.

## Why
- It's the only option where the language files themselves stop a broken build. That turns FR-8 into something the compiler enforces rather than a check we have to remember.
- It downloads only the messages a page uses, in one language, which fits the data budget.
- It's framework-neutral, so it survives the ADR-0001 choice either way.
- Fallback if it ever blocks us: the hand-rolled loader, because the JSON files stay the same.

## Consequences
- Message keys may need renaming from `app.name` to `app_name` style if Paraglide requires valid identifiers. This will be done once, in M1 step 4.
- **Language roadmap** (confirmed by owner 2026-11-21, based on South Africa's most common first languages):
  1. Launch: English (`en`) and isiZulu (`zu`, the most common first language), plus a pseudo-locale for development only
  2. Next: isiXhosa (`xh`) and Afrikaans (`af`)
  3. Then by pilot region, e.g. Sepedi (`nso`) and Setswana (`tn`) for Tshwane/Pretoria schools
  4. Every language stays marked "needs review" until a native speaker checks it
- A CI check lists untranslated strings per language. It warns for non-English languages and fails only for English.
- **Owner action:** find a native-speaker reviewer for isiZulu before launch.
